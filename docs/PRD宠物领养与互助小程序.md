## 1. 产品概述与目标

**一句话定位**：一个零金钱交易、AI 助力的宠物领养与互助平台，连接「送养人」与「领养人」，并提供养宠科普与地图寻宠互助；通过微信一键登录 + 平台云开发 + 免密钥大模型，低成本、跨端（小程序/H5/App）运行。

**产品原则（已拍板，必须遵守）**：
1. 发布端多端发布（微信小程序 + H5 + App），使用 uniapp 编译。
2. 后端/数据采用平台云开发/云服务（uniCloud 或 WorkBuddy 云数据库 + 免密钥大模型）。
3. AI 科普问答模型使用平台免密钥大模型（零成本接入，AI 成本越低越好）。
4. 登录采用微信授权一键登录（小程序端），以 openid 构建账号体系。
5. **平台不涉及任何金钱交易**；所有沟通在应用内会话完成，联系方式仅在会话中交换、不公开展示。
6. 必须是「AI＋」产品：**AI 管理员**为 V1.0 必备，负责内容审核、合规与辅助运营，减少人工。

**建议北极星指标（North Star）**：
> **月成功领养配对数** = 领养人点击「我要领养」后经平台会话向发帖人成功发送联系方式、且发帖人「接受」的配对数量。

理由：该指标同时反映供给（帖子数）、需求（领养意向）与平台信任（接受率），直接对应产品核心价值「促成负责任领养」，且不受金钱指标干扰。

**阶段护栏指标（Guardrails）**：
- 内容安全：AI 审核覆盖率 ≥ 95%，违规帖平均处理时长 < 30 分钟。
- 用户留存：新用户 7 日留存率（V1.0 目标 ≥ 25%）。
- AI 成本：单用户日均大模型调用成本低于设定预算阈值（见非功能第 5 节）。

## 2. 用户角色与画像

| 角色 | 身份说明 | 核心诉求 | 典型场景 |
| --- | --- | --- | --- |
| **发帖人（送养人）** | 有主宠物需送养、或救助流浪宠物的个人/志愿者 | 快速、安全地找到负责任的领养人；避免被骚扰或用于繁殖/食用 | 搬家无法养猫，发布英短领养帖；流浪狗救助后发布领养 |
| **领养人** | 想领养宠物的用户 | 浏览可靠帖子、了解宠物详情、安全对接送养人 | 想养一只温顺犬，筛选本地帖子并申请领养 |
| **寻宠人** | 宠物走失的主人（P2） | 在地图标注丢宠、快速触达附近人群 | 狗走失，地图标注并描述特征 |
| **科普作者** | 有养宠经验的用户/机构 | 分享经验、建立影响力 | 发布「幼猫喂养误区」科普帖 |
| **游客** | 未登录/未注册用户 | 有限浏览、被转化注册 | 朋友圈看到链接，H5 打开浏览帖子 |
| **AI 管理员** | 平台侧自动化审核与运营角色（非人类） | 7×24 审核违规内容、辅助运营、降本 | 实时审核新帖、拦截广告/敏感词、生成内容摘要 |

## 4. 带优先级的用户故事（含验收标准 AC）

### P0 · V1.0 必须

**US-01（发帖人 / 发布领养帖）**
作为**发帖人**，我希望填写结构化表单发布待领养宠物帖（含照片、健康状态、送养原因），以便负责任的领养人快速了解并申请。
- AC1：必填项（品种、年龄、性别、健康状态、所在地、送养原因、≥1 张照片）校验通过方可发布。
- AC2：发布后帖子进入审核队列，AI 审核通过后在列表可见（默认 ≤ 5 分钟）。
- AC3：支持编辑、撤下、重新上架，状态实时同步。

**US-02（领养人 / 浏览与筛选）**
作为**领养人**，我希望按品种/地点/年龄等条件筛选并查看帖子详情，以便找到合适的宠物。
- AC1：列表支持至少品种、所在地、年龄、性别、健康状态 5 个维度筛选 + 关键词搜索。
- AC2：详情页展示全部结构化字段与照片；联系方式**不直接显示**。
- AC3：筛选结果支持分页/下拉加载，空结果有引导文案。

**US-03（领养人 / 我要领养 + 会话）**
作为**领养人**，我希望对心仪宠物点击「我要领养」并进入内置会话，以便与发帖人沟通。
- AC1：点击后自动创建会话并通知发帖人。
- AC2：会话内可发送文字、图片、联系方式（手机号/微信等）。
- AC3：发帖人可对领养意向「接受」或「拒绝」，状态回写帖子。

**US-04（发帖人 / 交换联系方式与决断）**
作为**发帖人**，我希望在会话中收到领养人的联系方式并选择接受或拒绝，以便完成对接且不公开隐私。
- AC1：联系方式仅会话双方可见，列表/详情页不展示。
- AC2：「接受」后该领养人标记为意向成功；「拒绝」后对方收到礼貌通知。
- AC3：同一帖子可并行接待多位领养人，最终「已领养」状态仅可标记一次。

**US-05（全用户 / 微信一键登录）**
作为**用户**，我希望微信授权一键登录，以便免注册使用平台。
- AC1：小程序端点击授权即登录，获取 openid 建号；首次登录引导补全昵称/头像。
- AC2：登录态持久化，跨页面/跨会话有效。
- AC3：H5/App 端有兼容登录方案（见 Q4）。

**US-06（全用户 / 消息通知）**
作为**用户**，我希望收到会话、领养意向、举报结果等通知，以便及时处理。
- AC1：站内消息中心聚合所有通知，未读有红点。
- AC2：关键事件（新领养意向、被接受/拒绝、举报结果）实时推送（小程序订阅消息/H5 站内）。

**US-07（全用户 / 举报）**
作为**用户**，我希望举报违规帖/用户，以便维护社区安全。
- AC1：举报需选择原因（广告/违规/重复/敏感/其他）并可选补充说明。
- AC2：举报进入 AI+人工复核队列，结果通知举报人。
- AC3：被多次举报帖自动降权/进入人工优先审核。

**US-08（AI 管理员 / 内容审核）**
作为**平台**，我希望 AI 管理员实时审核所有新帖与问答，以便低成本拦截违规内容。
- AC1：新帖发布即触发审核，违规（广告/敏感词/重复/图片违规）自动拦截或打标。
- AC2：审核结果（通过/拦截/待人工）写入记录，可审计。
- AC3：误判有兜底申诉通道（见第 6 节）。

### P1 · V1.0 建议

**US-09（科普作者 / 发布经验帖）**
作为**科普作者**，我希望发布图文经验帖，以便分享养宠知识。
- AC1：支持图文编辑、分类标签；发布前经 AI 合规审核。
- AC2：发布后进入科普信息流，可被搜索与收藏。

**US-10（用户 / AI 科普问答）**
作为**用户**，我希望与免密钥大模型对话提问宠物问题，以便获得养宠指导。
- AC1：对话式界面，问题经合规过滤后调用大模型。
- AC2：回答可附「仅供参考，必要时就医」免责提示。
- AC3：单会话有长度/频率限制以控成本（见非功能 5）。

**US-11（用户 / 收藏）**
作为**用户**，我希望收藏帖子/科普，以便在「我的」中回顾。
- AC1：列表与详情均可收藏/取消，收藏列表按时间排序。

**US-12（AI 管理员 / 摘要标签）**
作为**平台**，我希望 AI 自动为帖子生成摘要与标签，以便提升检索与推荐。
- AC1：新帖通过审核后自动生成一句话摘要 + ≤5 标签。
- AC2：标签可被搜索与筛选复用。

### P2 · V1.0 之后（含地图寻宠）

**US-13（寻宠人 / 地图标注）**
作为**寻宠人**，我希望在地图标注丢宠位置与特征，以便附近用户帮忙留意。
- AC1：支持地图选点 + 上传照片 + 特征描述 + 走失时间。
- AC2：标注经审核后上图，默认公开位置模糊到街道级（见 Q3）。

**US-14（用户 / 查看附近寻宠）**
作为**用户**，我希望查看附近/全量寻宠标记，以便提供帮助。
- AC1：地图聚合标记，支持范围（1/3/5km）筛选。
- AC2：点击标记查看详情与「我找到了」告知入口。

**US-15（用户 / AI 寻宠提醒，创新点）**
作为**用户**，我希望系统基于我的位置与浏览偏好推送附近寻宠提醒，以便及时协助。
- AC1：基于地理位置与历史行为的轻量推送，可关闭。

## 5. AI 管理员设计

### 5.1 审核范围
- **内容审核**：领养帖、科普帖、用户资料、评论/会话中主动发送的违规内容。
- **问答合规**：AI 科普问答的提问与回复合规过滤。
- **反作弊**：广告/引流/重复发帖/批量注册识别。
- **敏感内容**：色情、暴力、违禁品、涉及食用猫狗等敏感词与图片识别。
- **辅助运营**：内容摘要、标签、健康度报表（P1/P2）。

### 5.2 触发时机
| 时机 | 动作 |
| --- | --- |
| 帖子/科普发布 | 同步实时审核（文本+图片） |
| 用户编辑内容 | 重新审核变更部分 |
| 用户举报 | 进入优先人工+AI 复核队列 |
| 问答每轮 | 提问与回复合规过滤 |
| 定时（如每日） | 全量存量内容抽检 + 报表 |

### 5.3 人机协同流程
```
内容发布 → AI 初审
   ├─ 通过        → 正常展示 + 生成摘要/标签
   ├─ 高风险/违规 → 自动拦截（不展示）+ 通知发布人原因
   └─ 疑似/不确定 → 打"待复核"标 → 进入人工队列（运营）
                                    ├─ 通过 → 展示
                                    └─ 违规 → 下架 + 记录
用户申诉 → 人工复核 → 误判则恢复 + 优化 AI 规则
```

### 5.4 误判兜底机制
- **申诉通道**：被拦截用户可在消息中心一键申诉，说明原因。
- **人工兜底 SLA**：疑似/申诉内容须在 24h 内人工复核（V1.0 可由运营兼职）。
- **反馈闭环**：误判案例回流至审核规则/提示词，持续降低误判率。
- **灰度与置信度**：低置信度一律转人工，宁可误判为人审也不错放高风险。

## 6. 非功能性需求

| 类别 | 要求 |
| --- | --- |
| **性能** | 列表首屏加载 ≤ 1.5s（P95）；发帖→审核可见 ≤ 5min；会话消息端到端延迟 ≤ 2s；支持 ≥ 1 万 DAU 平滑运行 |
| **安全** | 传输 HTTPS/TLS；openid 不落地明文泄露；会话内容加密存储；接口鉴权防刷（限频、签名）；防 XSS/注入 |
| **隐私与合规** | 联系方式仅会话双方可见，服务端不公开索引；遵循《个人信息保护法》，明示隐私政策与授权范围；未成年保护（见 Q5）；地理位置模糊化（见 Q3） |
| **跨端兼容** | uniapp 编译：微信小程序 / H5 / App 三端功能对齐；H5 受微信外链限制需兼容方案；图片/会话在各端一致体验 |
| **AI 成本控制** | 仅用免密钥/平台大模型，零 API 费用；问答设单用户日调用上限（如 20 次）与上下文长度上限；审核用轻量模型优先；监控单日总 token 消耗并告警 |

### 8.1 信息架构（IA）

### 8.2 关键页面线框（文字稿）
- **首页**：顶部搜索 + 三个圆形快捷入口；下方「为你推荐」双列卡片流，卡片含封面图、品种·性别·年龄、所在城市、状态角标（待领养/已预定）。

- **AI 问答页**：对话气泡，顶部标注「AI 生成，仅供参考」；输入框 + 字数限制提示。
- **发布帖**：分步表单（①基本信息 ②照片 ③健康与性格 ④送养原因），每步必填校验，提交即进入审核 loading。

## 11. 待确认问题清单（Top 优先）

1. **Q1 · 平台外引导**：领养人/发帖人在会话交换联系方式后，是否允许在聊天中引导至微信/电话等平台外沟通？还是要求全程留在应用内？（影响合规与留存设计）
2. **Q2 · 内容审核合规边界**：AI 管理员对「疑似违规」的处置权限到哪？自动下架还是仅打标？涉及人工复核的 SLA 与责任人如何定？敏感词库由谁维护？
3. **Q3 · 地图服务跨端选型**：地图寻宠使用哪家地图 SDK？小程序/H5/App 三端地图能力是否一致？用户位置是否模糊化（街道级）以保护隐私？
4. **Q4 · 多端登录兼容**：微信一键登录仅小程序端可用；H5/App 端登录方案用「微信 H5 授权」还是「手机号一键登录」？账号体系如何在三端打通（同一用户识别）？
5. **Q5 · 敏感词与未成年人保护**：是否限制未成年人发布领养/领养人资格？涉及猫狗食用等极端敏感内容的处置与上报机制？是否需实名/年龄校验？

### 11.1 已确认决策（2025-11-02，team-lead 与用户拍板）
- **Q1 平台外沟通 → 允许但风险提示**：会话内可交换联系方式并引导至微信/电话等平台外沟通，但发送/跳转时弹安全提示（防诈骗、禁止线下金钱交易）。
- **Q4 多端登录 → 微信授权 + 手机号兜底**：小程序端微信一键登录；H5 用微信 H5 授权、App 用微信开放平台授权；统一以手机号作为账号主键打通三端。
- **Q2 AI 审核处置 → 先打标 + 人工复核**：AI 仅做风险打标与拦截高风险，疑似内容进人工队列（运营 SLA 24h）；保留申诉通道。
- **Q3 地图选型 → 街道级模糊 + 高德/腾讯地图**：丢宠位置模糊到街道级保护隐私，统一高德/腾讯 SDK，三端能力对齐。
- **Q5 未成年人保护（默认）**：限制未成年人发布领养帖与作为领养人资格，需监护人/实名校验；涉及猫狗食用等极端敏感内容一律 AI 拦截并上报。
