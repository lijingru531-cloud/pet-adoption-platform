# [BUG] 接口统一返回字段为 message，与规范约定的 msg 不一致

| 项目 | 内容 |
|---|---|
| 缺陷编号 | BUG-S4-002 |
| 严重级别 | 轻微 |
| 优先级 | P3 |
| 所属模块 | 接口契约（REQ-13） |
| 发现人 | 张艾佳（执行 TC-API-001） |
| 开发责任人 | 李廷 |
| 发现版本 | main @ 2026-11-16，USE_MOCK=true |
| 关联用例 | TC-API-001 验证统一返回结构_抽样调用各模块接口_信封字段一致 |

## 环境
接口层测试（Mock 与云函数均抽样），Node 22 直接调用 services。

## 复现步骤
1. 调用 `post.list`、`post.detail`、`science.list`、`ai.chat`、`search`、`report.create` 六个接口；
2. 打印返回对象的所有键；
3. 与《PBL项目规范》第 6 条「统一返回 `{code, msg, data}`」比对。

## 预期结果
所有接口返回 `{ code, msg, data }`，成功时 `code=0`、`msg='ok'`。

## 实际结果
六个接口均返回 `{ code, data, message }`：字段名为 `message`，且顺序为 data 在前；失败时同样使用 `message`。前端多处按 `res.message` 取值，与规范文本不一致。

## 根因定位
`src/constants/errorCode.js` 中的 `ok()` / `fail()` 统一封装使用了 `message` 字段，全仓库调用点随之扩散（grep `message:` 共 20+ 处）。

## 影响
本身不影响功能，但违反接口规范；新人按规范写 `res.msg` 会拿到 `undefined`，错误提示静默丢失；答辩/评审时属于规范项扣分点。

## 修复建议（二选一，团队评审后统一）
1. **推荐**：封装层改为 `{ code, msg, data }`，并在 `utils/request` 增加兼容层 `const m = res.msg ?? res.message`，一次性替换调用点；
2. 若坚持 `message`，需修改《PBL项目规范》第 6 条并同步给两人，不能代码与文档各说一套。

## 验收标准
- [ ] `ok()/fail()` 输出 `{code, msg, data}`；
- [ ] 全仓库 `grep -rn "res.message" src/` 结果为空；
- [ ] 六个抽样接口返回键名一致；
- [ ] TC-API-001 复测通过。
