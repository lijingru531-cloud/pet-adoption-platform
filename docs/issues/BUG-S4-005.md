# [BUG] 被合规拦截的违规提问仍扣减 1 次日配额

| 项目 | 内容 |
|---|---|
| 缺陷编号 | BUG-S4-005 |
| 严重级别 | 轻微 |
| 优先级 | P3 |
| 所属模块 | AI 科普问答（REQ-09） |
| 发现人 | 张艾佳（执行 TC-AI-006 时顺带发现） |
| 开发责任人 | 李廷 |
| 发现版本 | main @ 2026-11-16，USE_MOCK=true |
| 关联用例 | TC-AI-006 验证AI违规问题拦截_输入极端敏感词_拦截且不返回答案 |

## 环境
微信开发者工具 + H5，Mock 模式。

## 前置条件
已登录，记录当日剩余次数（首页气泡显示「剩余 20 次」）。

## 复现步骤
1. 发送一条含极端敏感词的提问，被拦截；
2. 观察剩余次数；
3. 再发送一条正常提问。

## 预期结果
被拦截的提问不消耗配额，剩余次数仍为 20；正常提问后为 19。

## 实际结果
被拦截后剩余次数变为 19，正常提问后为 18，用户因违规输入被动损失次数。

## 根因定位
`src/services/ai.js` `chat()`：

```js
if (!enforceQuota(userId)) { ... }        // ← 先扣配额（内部已 storage.set(used+1)）
const filter = complianceFilter(question);
if (filter.level === 'block') { ... }     // ← 后判合规，拦截时配额已扣
```
`enforceQuota` 把「检查」与「扣减」耦合在一个函数里，天然无法回滚。

## 修复建议
拆成两步，先判合规再扣减：
```js
if (!checkQuota(userId)) return { code: AI_QUOTA_EXCEEDED, ... };
const filter = complianceFilter(question);
if (filter.level === 'block') return { code: CONTENT_BLOCKED, ... };
consumeQuota(userId);      // 仅合规通过后调用
```
或保留 `enforceQuota` 但增加 `rollbackQuota(userId)`，在拦截分支回退。推荐前者。

## 验收标准
- [ ] 被拦截提问前后剩余次数不变；
- [ ] 正常提问仍准确 -1；
- [ ] 第 20 次成功、第 21 次返回 `AI_QUOTA_EXCEEDED`（TC-AI-007 回归）；
- [ ] TC-AI-006 复测通过。
