## 环境
微信开发者工具 1.06（iPhone 13 / iOS 17）+ H5（Chrome 120）；Mock 数据源。

## 前置条件
库中存在至少 1 条 `status=pass` 的科普帖，标题或标签含「猫」。

## 复现步骤
1. 进入全局搜索页 `/pages/search/index`，输入「猫」并回车；
2. 结果列表出现「领养」与「科普」两类条目；
3. 点击任意一条类型标签为「科普」的结果。

## 预期结果
进入该科普帖详情页，展示对应标题与正文，浏览量 +2，返回后搜索词与结果仍在。

## 实际结果
停留在科普列表 tab，未定位到被点击的帖子。控制台可见执行了 `uni.switchTab({url:'/pages/science/list'})`，未携带 `id`，列表页也不接收 `id` 参数，用户需要自己再翻找。

## 根因定位
`src/pages/search/index.vue:142-149`

```js
function onItemClick(item) {
  if (item._type === 'post') {
    uni.navigateTo({ url: `/pages/adopt/detail?id=${item._id}` });
  } else {
    // 科普帖：进入科普列表页并打开详情（或扩展独立详情页）
    uni.switchTab({ url: '/pages/science/list' });   // ← id 丢失
  }
}
```

科普详情为 `pages/science/detail?id=xxx`（非 tabBar 页），应使用 `navigateTo` 并透传 `id`。

## 修复建议
```js
uni.navigateTo({ url: `/pages/science/detail?id=${item._id}` });
```
若详情页尚未注册到 `pages.json`，先补注册；如需保留「回到列表」的兜底，可在详情页加返回列表入口，而不是丢弃 id。

## 验收标准
- [ ] 点击任一科普结果进入对应详情，标题与列表项一致；
- [ ] 点击领养结果行为不变；
- [ ] 返回搜索页后关键词与结果列表保留；
- [ ] TC-SRC-007 复测通过。
